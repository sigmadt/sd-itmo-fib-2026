# Сервис уведомлений: техническое задание

Интернет-магазин сообщает покупателям и сотрудникам о событиях с заказами: заказ отправлен, нужно собрать заказ, срочное сообщение менеджеру. Сервис уведомлений принимает сообщение и доставляет его по нужному каналу.

Сеть в учебной версии не используется: каналы печатают, что бы они отправили. По этому выводу и проверяется поведение (`expected_output.txt`).

---

## 1. Сообщение

| Поле | Что значит | По умолчанию |
|---|---|---|
| `to` | получатель: адрес почты, телефон или ник в Telegram | обязательно |
| `body` | текст | обязательно |
| `subject` | тема, нужна только письму | пусто |
| `cc` | копия письма | нет |
| `priority` | `normal` или `high` | `normal` |
| `silent` | Telegram без звука | нет |
| `retries` | сколько раз повторять при ошибке, если нужно не так, как в настройках | как в настройках |
| `template` | шаблон текста, `{body}` заменяется на текст | нет |
| `signature` | добавлять подпись «С уважением, магазин» | да |
| `footer` | еще одна строка в конце | нет |

**Итоговый текст** собирается так:
1. если есть шаблон, в нем `{body}` заменяется на `body`, иначе берется `body`;
2. если включена подпись, с новой строки добавляется «С уважением, магазин»;
3. если есть `footer`, он добавляется с новой строки.

---

## 2. Каналы

| Канал | Что печатает при отправке | Когда ошибка |
|---|---|---|
| `email` | строку `[email] from=<отправитель> to=<кому>`, затем ` cc=<копия>`, если она есть, затем ` subject="<тема>" priority=<приоритет>`. Потом каждую строку итогового текста с отступом в два пробела | никогда |
| `sms` | ничего сам, печатает шлюз провайдера | шлюз ответил не 200 |
| `telegram` | `[telegram] <кому>: <итоговый текст>`, и ` (без звука)` в конце, если `silent` | никогда |

Отправитель писем берется из настроек.

**SMS идут через шлюз провайдера** `LegacySmsGateway`. Это чужой код, его нельзя менять. У шлюза свой интерфейс:
- номер передается только цифрами: `+7 (900) 111-22-30` превращается в `79001112230`;
- текст передается байтами в кодировке cp1251;
- шлюз возвращает код: 200 доставлено, 503 провайдер временно недоступен;
- шлюз сам печатает `[sms] <номер>: <текст>` при успехе и `[sms-gateway] 503 для <номер>` при ошибке.

Неизвестный канал это ошибка программы, а не сообщения: сервис должен сообщить о ней сразу.

---

## 3. Повторы и журнал

- Если отправка не удалась, сервис повторяет ее. Всего попыток не больше `retries + 1`. Число повторов берется из сообщения, а если там не задано, из настроек (по умолчанию 2).
- Если журнал включен в настройках, перед каждой попыткой печатается `[log] <канал>, попытка <N>, кому <получатель>`.
- Если все попытки не удались, печатается `[log] <канал> не доставлено: <получатель>`.
- Правила одинаковы для всех каналов.

---

## 4. Группы получателей

Сообщение можно отправить группе. Группа состоит из получателей и других групп, вложенность любая.

- При отправке группе печатается `[group] <название группы>`, затем сообщение уходит каждому участнику по порядку, во вложенные группы так же.
- Участникам группы уходит только текст: без темы, без подписи, без звука, с обычным приоритетом.

---

## 5. Счетчик

Сервис считает доставленные сообщения. Каждое успешно доставленное сообщение увеличивает счетчик на 1, неудачные попытки не считаются.

---

## 6. Настройки

| Настройка | По умолчанию |
|---|---|
| адрес отправителя писем | `shop@example.com` |
| число повторов | 2 |
| журнал | включен |

---

## 7. Сценарий «заказ отправлен» (`main`)

1. Покупателю письмо: тема «Заказ 1042», текст с трек-номером, копия в `orders@example.com`, высокий приоритет, с подписью.
2. Покупателю SMS: высокий приоритет, без подписи. Шлюз с первого раза отвечает 503, со второго доставляет.
3. Складу в Telegram: группа «Склад», в ней `@petrov` и вложенная группа «Ночная смена» (`@ivanova`, `@sidorov`). Текст «Собрать заказ 1042».
4. Менеджеру в Telegram: шаблон «Срочно: {body}», без повторов, без подписи, с подвалом «Отдел логистики».
5. Печать числа доставленных сообщений.

---

## 8. Что будет меняться

Сервис будут развивать. Именно поэтому важно, как он устроен внутри, а не только что он печатает:

- добавятся каналы Push и Slack. Добавление канала не должно требовать правки остальных каналов;
- повторы и журнал понадобятся всем новым каналам, причем одинаковые;
- провайдера SMS могут сменить на другого, с другим интерфейсом;
- для тестов нужно запускать сервис с другими настройками, например без повторов, не трогая остальной код;
- у сообщений станет больше опций, и создание сообщения не должно превращаться в угадывание, что значит `True` на шестом месте.

Это и есть задачи рефакторинга на практике.
